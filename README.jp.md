# InputSourceSwitcher

*[English README](README.md)*

macOS の「入力ソース切り替えが、しばらく切り替えていないと最初の一回を取りこぼす」
問題に対処するための、メニューバー常駐の小さなユーティリティです。
`^Space`（Control+スペース）などのショートカットを横取りし、OS の切り替え処理を
経由せず**直接**入力ソースを切り替えることで、取りこぼしを避けます。

Swift 製・単一ファイル。外部ライブラリ依存なし。ソースからビルドして使います。

---

## 背景 — こういう症状に困っていませんか

- しばらく入力ソースを切り替えずにいると、`^Space` を押しても**最初の 1〜2 回が
  無反応**で、少し遅れて切り替わる
- 日本語⇄英語だけでなく、英語⇄他の西欧言語のレイアウトでも起きる
- IME を変える／ショートカットを変える／「次のソース」ではなく「前のソースを選択」
  だけ使う、などを試しても解決しない

これは古くから報告されている macOS の挙動で、ショートカット入力に対する
入力ソース切り替え処理が、一定時間その処理が呼ばれないと「冷えて」しまい、
次の一回目を取りこぼすことが原因と考えられます。設定変更では根本解決しにくいため、
本ツールは **OS のショートカット処理をそもそも経由しない**方法で切り替えます。

---

## 仕組み

1. `CGEventTap`（キーイベントの横取り）で、設定したショートカット
   （既定は `^Space`）の押下を捕まえ、アプリには渡さず握りつぶします。
   対になるキー解放（key-up）も一緒に握りつぶすので、キー状態を自前で
   追跡するアプリが「押しっぱなし」と誤認することもありません。
2. その場で **TIS API を直接呼んで**入力ソースを切り替えます。切り替え先は、
   指定した 2 ソースの往復、または直前に使っていたソースです。
3. 切り替え直後にもう一度同じソースを選び直す「二段撃ち」を行い、
   IME（ATOK など）の活性化取りこぼしを防ぎます。

OS のショートカット処理を通らないため、その処理が「冷える」ことに起因する
取りこぼしが構造的に起きません。

なお、横取りのコールバック自体は即座に戻し、切り替えの実処理はメインキューへ
渡しています。コールバック内で時間のかかる処理を行うと、macOS がタップを無効化
（`tapDisabledByTimeout`）してしまい、直したはずの取りこぼしが再発するためです。

---

## 既知の挙動

切り替え時に、メニューバーの入力ソース表示が一瞬チラつくことがあります。これは
確実に切り替えるため短時間に複数回ソースを選択している（切り替え＋後追いの再選択）
ためで、動作上の問題はありません。

## 動作環境

- macOS 13 (Ventura) 以降（ログイン起動に `SMAppService` を使用）
- Xcode Command Line Tools（`swiftc` が使えれば OK）
  - 未導入なら `xcode-select --install`
- Apple Silicon / Intel どちらも可

## ビルドとインストール

```bash
git clone https://github.com/rn10/InputSourceSwitcher.git
cd InputSourceSwitcher
./build.sh     # コンパイルして InputSourceSwitcher.app を生成（アドホック署名・アイコン入り）
./install.sh   # /Applications へインストール
```

`build.sh` は `AppIcon.iconset` から `iconutil` でアプリアイコン（`AppIcon.icns`）も
自動生成するので、追加の手作業は不要です。

`install.sh` は `/Applications` へのコピー、quarantine 属性の除去に加え、
**古いアクセシビリティ登録のリセット**を行います（後述）。

## 初回起動とアクセシビリティ権限

キーイベントを横取りするため、**アクセシビリティ権限が必須**です。

1. InputSourceSwitcher を起動（`/Applications` でダブルクリック）
2. アクセシビリティの許可を求められたら許可
   （出ない場合は「システム設定 > プライバシーとセキュリティ > アクセシビリティ」で
   InputSourceSwitcher を追加してオン）
3. 許可すると 1〜2 秒で自動的に有効になります。**再起動は不要**です。

30 秒経っても有効にならない場合は、一覧に古い登録が残っている可能性があります。
アプリが案内を表示するので、後述の「更新について」を参照してください。

## 使い方

メニューバーのアイコンをクリックすると、以下の項目があります。

- **有効** — 横取りの ON/OFF。OFF にすると `^Space` は素通しになります
  （システム設定で入力ソース系ショートカットを登録したいときなどに一時 OFF に）
- **トグルする 2 ソースを選択** — 有効な入力ソースが名前で一覧表示されます。
  ここで **2 つ選ぶ**と、`^Space` はその 2 つだけを往復します。
  「選択を解除（自動に戻す）」で、直前のソースへ切り替える自動モードに戻ります。
- **修飾キー** — 横取り対象の修飾キー（Control / Option / Command / Shift）を選択。
  最低 1 つは必須で、最後の 1 つは外せません。すべて外すと素のスペースキーが
  条件に一致し、全アプリでスペースが入力できなくなるためです。
- **ログイン時に起動** — `SMAppService` で自動起動を登録／解除
- **アクセシビリティ設定を開く…**
- **ログを書き出す…** — 直近 1 時間のログをデスクトップにテキストで保存し、
  Finder で表示します。ターミナルを使わずに不具合の状況を共有できます。
- **アンインストール…** — 下記参照
- **終了**

UI 言語はシステムの言語設定（日本語／英語）に従います。選んだ設定は保存され、
次回起動時も維持されます。なお横取りするキー自体はスペース固定です
（変更する場合は `main.swift` 冒頭の `switchKeyCode` を編集）。

ログイン起動を確実にするには、アプリを `/Applications` に置いたままにしてください
（`SMAppService` は配置場所が安定していることを前提とします。`install.sh` がそこへ
配置します）。

同時に動くのは 1 つだけです。2 つ目を起動した場合はその旨を表示して終了するので、
両方が切り替えを実行して往復してしまうことはありません。

## ログ

ログは独自ファイルではなく、**macOS の統合ログ**に記録します。横取りの
コールパスからファイル I/O を排除でき、ローテーションや後片付けも不要になるためです。

直近 1 時間を表示：

```bash
log show --predicate 'subsystem == "com.naito.InputSourceSwitcher2"' \
         --last 1h --info --debug
```

リアルタイムで追う：

```bash
log stream --predicate 'subsystem == "com.naito.InputSourceSwitcher2"' --level debug
```

「コンソール.app」なら検索欄に `subsystem:com.naito.InputSourceSwitcher2` と入力し、
メニューの「アクション > デバッグメッセージを含める」をオンにすると個々の切り替えも
表示されます。

メニューの **「ログを書き出す…」** を使えば、これらを覚えていなくても構いません。

記録される内容：

| レベル | 保存 | 内容 |
|---|---|---|
| `notice` | 永続化 | 起動、タップ設置、権限付与、設定変更 |
| `error` | 永続化 | タップ生成失敗、**タップの自動復帰**、ログイン項目のエラー |
| `debug` | メモリ上 | 個々の切り替え（`switch A -> B (OSStatus 0)`） |

しばらく正常に動いていたのに切り替わらなくなった場合、手がかりになるのは
「タップの自動復帰」の行です。

## 更新について

**アンインストールは不要**です。ビルドし直してインストールするだけで更新できます。

```bash
./build.sh
./install.sh
```

設定（トグル対象のソース、選んだ修飾キー）は引き継がれます。

**なぜ `install.sh` がアクセシビリティ権限をリセットするのか。**
本アプリはアドホック署名のため、ビルドのたびに署名のハッシュが変わり、macOS は
別アプリとみなします。その結果、以前の許可は無効になりますが、一覧には
**チェックが入ったまま残る**ため、権限が有効なように見えてしまいます。
チェックを外して入れ直しても直りません。

そこで `install.sh` は
`tccutil reset Accessibility com.naito.InputSourceSwitcher2` を実行し、
次回起動時にあらためて許可を求めるようにしています。macOS のバージョンによっては
このコマンドが失敗することもあるので、その場合は手動で行ってください。

「システム設定 > プライバシーとセキュリティ > アクセシビリティ」→
InputSourceSwitcher を選択 → **「−」ボタン**で削除 → あらためて追加。

なお、1 日に何度もビルドし直すような使い方で権限の付け直しが煩わしい場合は、
コード署名用の自己署名証明書を 1 つ作成し、`build.sh` の `--sign -` を証明書名に
変えると署名が一定になり、権限が維持されます。この証明書は自分の Mac 内でのみ
有効で、通常の利用には不要です。

## アンインストール

メニューバーの **「アンインストール…」** を選んで確認すると、ログイン項目の解除、
設定の削除、アプリ本体のゴミ箱への移動をまとめて行います。続けて
アクセシビリティ設定が開くので、そこから InputSourceSwitcher の項目を削除して
ください。この項目だけは自動では削除できないため、手動での削除が必要です。

ログは統合ログに記録されており、一定期間で自動的に消えます。

## 変更履歴

**1.2**

- 長時間アイドル後の切り替えで IME の活性化が遅れるケースを拾えるよう、
  後追いの再選択タイミングを調整。
- メニューバー表示の一瞬のチラつきを「既知の挙動」として明記。
- メニューにバージョン表示と「GitHub で開く」リンクを追加。

**1.1**

- 横取りのコールバックをブロックしないように変更。切り替えはメインキューへ渡し、
  「二段撃ち」の待機も `usleep` をやめて後追い実行に。負荷時にタップが
  タイムアウトで無効化されるのを防ぎます。
- キー押下と対になるキー解放（key-up）も握りつぶすように変更。
- 修飾キーを全部外せないように制限（素のスペースが全アプリで飲み込まれるのを防止）。
- 多重起動を防止。
- ログを `~/Library/Logs/InputSourceSwitcher.log` から統合ログへ移行し、
  **「ログを書き出す…」** を追加。
- `install.sh` が古いアクセシビリティ登録をリセットするようになり、
  上書き更新ができるように（設定は引き継がれます）。
- 起動 30 秒後も権限が有効にならない場合、対処方法を案内するように。
